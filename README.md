# AutoTestReport Hub

**AutoTestReport Hub** — вебзастосунок для централізованого збирання, зберігання та аналізу результатів автоматизованого тестування програмного забезпечення. Він імпортує готові звіти JUnit XML і JSON, формує історію запусків і надає узагальнені показники якості.

Застосунок не запускає тести: звіти створюються тестовим середовищем або CI-системою, а AutoTestReport Hub приймає та аналізує їх.

> Докладні вимоги, архітектуру, моделі даних і сценарії роботи наведено в [документі проєктування](docs/PROJECT_DESIGN.md).

## Можливості

- Реєстрація, вхід і захищений доступ до ресурсів користувача.
- Створення та керування проєктами.
- Імпорт звітів у форматах JUnit XML і JSON через вебінтерфейс або API.
- Збереження структурованих результатів і вихідного файла звіту.
- Перегляд історії запусків, деталей тестів і показників `passed`, `failed` та `skipped`.
- Виявлення нестабільних тестів за зміною результату між запусками.
- Формування автономного HTML-звіту та сторінки для друку.

Показник успішності обчислюється за виконаними тестами; пропущені тести (`skipped`) не входять до його знаменника. Тест позначається як нестабільний, якщо однакові клас і назва тесту мали результати `passed` та `failed` у різних запусках.

## Технології

| Частина | Технології |
| --- | --- |
| Backend та REST API | Python, FastAPI, Pydantic |
| Зберігання даних | SQLAlchemy, Alembic, SQLite; налаштовувана URL-адреса бази даних |
| Frontend | React, TypeScript, Vite |
| Формати імпорту | JUnit XML, JSON |

Архітектурно застосунок є модульним монолітом: клієнтський інтерфейс взаємодіє з REST API, а API використовує сервіси, моделі та парсери звітів.

## Вимоги

- Windows і PowerShell.
- Python 3.12.
- Node.js із npm.

## Локальний запуск

У PowerShell перейдіть до кореневої теки проєкту та виконайте початкове налаштування:

```powershell
.\setup.ps1
```

Скрипт створить віртуальне середовище, підготує локальну конфігурацію, встановить залежності, застосує міграції бази даних і збере frontend. Після успішного налаштування запустіть застосунок:

```powershell
.\run.ps1
```

Вебінтерфейс буде доступний за адресою <http://127.0.0.1:8000>. Документація REST API FastAPI доступна на <http://127.0.0.1:8000/docs>.

## Конфігурація та дані

Під час початкового налаштування створюється локальний файл `.env`. За замовчуванням застосунок використовує SQLite та зберігає базу даних у теці `data/`. Для іншого сумісного сховища можна задати `DATABASE_URL` у `.env`.

Файли `.env`, локальна база даних і згенеровані артефакти призначені для локального середовища та не мають потрапляти до системи контролю версій.

## Перевірки

У теці `tests/` розміщені модульні та інтеграційні тести, а в `tests/TEST_CASES.md` — функціональні сценарії. Для запуску тестів потрібен pytest:

```powershell
.\.venv\Scripts\python.exe -m pip install pytest
.\.venv\Scripts\python.exe -m pytest
```

## Структура проєкту

```text
app/          backend, API, сервіси, моделі та схеми
docs/         проєктна документація
frontend/     клієнтський вебінтерфейс
migrations/   міграції схеми бази даних
samples/      приклади звітів для імпорту
tests/        автоматизовані тести й функціональні сценарії
```
